## Context

Deliverable: new extension package whose OMP footer status line shows, whenever DeepSeek models are *actually in use* (main or subagent, incl. transient mid-session fallback): peak/off-peak state in the user's local time, countdown to the next window boundary, per-model prices fetched live from the official pricing doc, remaining DeepSeek balance, and DeepSeek cost of the whole session. ### Phase 3 — Pricing + window engine (pure; `lib/pricing.ts`, `lib/window.ts`)
`lib/pricing.ts`:
- Official price tables exist per currency locale (both verified live 2026-09-06, both need the trailing slash — bare paths serve stale "first call" content): USD = `https://api-docs.deepseek.com/quick_start/pricing/`, CNY = `https://api-docs.deepseek.com/zh-cn/quick_start/pricing/`. Map `PRICE_URLS = { USD: <en>, CNY: <zh-cn> }`; `fetchPricing(currency: "USD"|"CNY"): Promise<{ok:true; data:PricingData} | {ok:false; error:string}>` picks the locale, fetch injected for tests. The parser never assumes USD.
- Parser reads the official page: price table rows + the schedule sentence. Normalized `PricingData`:
  - `models: Record<string, {peak:{inHit,inMiss,out}, offPeak:{inHit,inMiss,out}}>` keyed by base ids `deepseek-v4-flash`, `deepseek-v4-pro`, `deepseek-v4-flash-vision-exp` (3 model columns per row group on both locale pages, verified). Parse the real `<table>` cells (peak vs off-peak column groups), not flattened text. Numeric scale is identical across locales (per 1M tokens; en in USD, zh-cn in CNY 元 — take each page's own numbers, never convert). `PricingData = {currency: "USD"|"CNY", models, schedule}`.
  - `schedule` (canonical UTC) parsed from the schedule sentence: en page states "01:00 - 04:00 and 06:00 - 10:00 UTC, Monday through Friday (all other hours are off-peak)"; zh-cn page states the same windows in 北京时间 "9:00 - 12:00、14:00 - 18:00" Mon–Fri. Parser detects the stated timezone token (`UTC` vs `北京时间`); for 北京时间 it subtracts 8 h (Asia/Shanghai, no DST) to produce the identical canonical spans `[{days:"mon-fri", start:"01:00", end:"04:00"}, {days:"mon-fri", start:"06:00", end:"10:00"}]`. `discount` computed = offPeak/peak input-miss ratio of the first model (0.5 in both locales, verified), never hard-coded. Test asserts the zh parse equals the en parse.
- Fetch policy is FETCH-ONCE-KEEP-FOREVER, PER CURRENCY: the table for a currency is fetched from its official locale page exactly once — first need (no cached parse for THAT currency AND segment visible; the needed currency comes from Phase 5's balance-currency determination) — then served forever with NO TTL and NO automatic re-fetch. The ONLY re-fetch is user-initiated: `/ds-statusline --force-refresh` re-fetches every currency that has a cache entry. Rationale: DeepSeek changes pricing rarely; the source-of-truth requirement is met per locale; the user owns re-sync. No third-party FX anywhere — cost is priced from the official table of the account's own currency.
- Cache (sibling persistence pattern): single JSON file `~/.omp/agent/extensions/deepseek-statusline/pricing-cache.json` (`getAgentDir()` = `~/.omp/agent` by default; NOT `config.yml` — that file is OMP-core-owned typed settings; this extension never reads or writes it) holding `{entries: {USD?: {fetchedAt, data}, CNY?: {fetchedAt, data}}}`. Serve each currency's entry regardless of age, forever, until `--force-refresh` atomically overwrites it. First-fetch failure with no entry for the needed currency → that currency shows `prices unavailable` (its prices + session cost suppressed), retry ≤ 5 min while visible until the first success. Force-refresh failure → keep existing entries and notify "refresh failed"; never delete the cache. Parser emits no rows/window → page changed: keep last parse, log once, notify on force-refresh.
- No offline price constants exist: prices/schedule/cost render only from data fetched from the official page — never fabricate; do not copy sibling `PRICING_TIERS` for display (Phase 4's cost engine is driven by fetched rows only; no last-resort constants).
`lib/window.ts` (pure, injected `now`):
- WEEKDAY multi-window recurrence. `phaseAt(nowMs, schedule)` → `{phase:"peak"|"off-peak", nextSwitchAtMs, countdownMs}` via epoch-instant math: peak iff UTC weekday Mon–Fri AND UTC time-of-day ∈ [01:00,04:00) or [06:00,10:00). Next boundary = earliest of span end (in peak) / next span start (in off-peak), incl. weekday wrap (Fri 10:00 → Mon 01:00; weekends all off-peak → next boundary Mon 01:00).
- `localClock(instantMs, tz)` for label "→ peak 08:00" — user IANA tz; default `Intl.DateTimeFormat().resolvedOptions().timeZone`, override = config `timezone` (Phase 8). DST-correct by construction (UTC schedule → instants → local format).
- `formatCountdown(ms)`: `Xh Ym` while > 60 s, `Ym Zs` below.
Tests (`tests/window.test.ts`): fixed instants — peak inside each span, off-peak gaps (00:30, 04:30, 10:30), Fri 10:00 → next Mon 01:00, Sat noon → Mon 01:00, boundary ±1 s, countdown values; local-clock rendering in `America/New_York` across a DST transition week and `Asia/Ho_Chi_Minh` (UTC+7, no DST). `tests/pricing.test.ts`: fixture = real page snapshot saved at impl time to `tests/fixtures/pricing-<yyyymmdd>.html` (trailing-slash URL); parser asserts ≥1 model with offPeak = 0.5×peak and Mon–Fri peak spans (assert against fixture values); fetch-once semantics with a mocked fetch counter — cache present at ANY age → zero fetch calls; no cache + fetch failure → `unavailable` + retry; no cache + success → persisted once; simulated `--force-refresh` → exactly one fetch and atomic overwrite; failed force-refresh keeps the old cache.

### Phase 4 — Usage aggregation + session cost (`lib/usage.ts`, `lib/cost.ts`)
- On `message_end` (assistant, `.usage` present) with `isDeepSeekModel(ctx.model)` — fires once per assistant message, i.e. per turn AND per tool-call step (real-time granularity) — accumulate in memory per session, bucketed per model × schedule phase: `{modelId, phase:"peak"|"offPeak", cacheHit, cacheMiss, output}` where `phase = phaseAt(event.ts).phase` from the current schedule; no schedule available yet → bucket "peak" (full rate, no discount). After EVERY such event, recompute session cost and status text and call `ctx.ui.setStatus` synchronously — the figure moves with each turn/tool call, not on a tick. Persist per-session ledger JSON at `agentDir/extensions/deepseek-statusline/ledger-{sessionId}.json`: `{sessionId, cwd, startTs, lastTs, buckets: <model×phase sums>}` — sibling debounce (≤1 write/s) and 30-day cleanup (ledger files only; never touch `pricing-cache.json`).
- Session cost estimate (`lib/cost.ts`), recomputed on every usage event, subagent ledger change, or pricing refresh: per bucket, `(cacheHit*hit + cacheMiss*miss + output*out)/1e6` using the row matching `modelId.startsWith(key)` and the bucket's own phase rows (offPeak buckets at off-peak prices, peak buckets at peak prices; before any schedule exists everything sits in the peak bucket = full rate). Unknown model (no row) → tokens counted as unpriced, rendered `+n unpriced`, never guessed. Table selection follows the Phase 5 display rule: the ONE chosen-currency official table prices every bucket (`displayCurrency` auto CNY-first, or pinned USD/CNY) — never two currencies in one line.
- Session-tree cost (whole session incl. subagents): main ledger + every ledger with `cwd === ctx.cwd && startTs >= mainStartTs - 60_000 && lastTs <= now` (or parent-session id filter per A3c when available). Recompute on main `message_end` + ledger-dir changes: `fs.watch` + 10 s fallback scan while a DeepSeek session is live. Subagent deltas roll in ≤ ~2 s.
Tests: fixture events/ledgers → exact sums per model×phase bucket (priced against the USD-table and CNY-table fixtures; flash vs pro; events straddling a peak/off-peak boundary land in their own buckets; cache-hit mix; schedule-missing events → full-rate peak bucket; unknown model → unpriced; subagent ledger arriving after main totals update); mocked `ctx.ui.setStatus` is invoked synchronously after each usage event.

### Phase 5 — Balance, key resolved from OMP core (`lib/balance.ts`)
- `GET https://api.deepseek.com/user/balance`, header `Authorization: Bearer <key>`. Key source: **`ctx.modelRegistry.getApiKeyForProvider("deepseek")`** (fallback: provider string from the last observed DeepSeek `ctx.model.provider`, Phase 1 A4c). No env, no config, no storage, no user input — same key OMP already uses for the requests. Guard: only call when a session ctx with `modelRegistry` is captured (skip ticks before the first `session_start`; never call at module load).
- Parse `balance_infos`; the rows ARE the user-currency determination ("currency first" — first balance fetch at session start / first visible tick), but the segment renders the ONE chosen display currency (rule below), never converting or summing rows and never comparing currencies numerically (a magnitude comparison would need an FX rate — excluded). USD-only → `bal $12.34`; CNY-only → `bal ¥110.00`; mixed under auto → CNY row → `bal ¥110.00` until the user pins USD.
- Cost display currency (drives the ONE official price table that prices the session buckets + the balance row rendered): config `displayCurrency` default `auto` → **CNY-first**: balance response contains a CNY row → CNY (zh-cn ¥ table); else a USD row → USD (en $ table); no rows yet (no auth configured, 401/network, or first fetch pending) → CNY (DeepSeek-native default). Rationale: a "smarter, larger balance wins" rule needs an exchange rate and third-party FX is excluded (official tables only), so auto resolves mixed accounts to CNY — the native currency, user-chosen; `/ds-statusline` or the YAML pins `displayCurrency: USD|CNY` any time. Currency flip: a first balance response may move auto off the CNY default (USD-only account) → display flips to USD and the en table is fetched then (per-currency cache; at most one extra first fetch ever).
- States: no DeepSeek auth configured in OMP (`getApiKeyForProvider` → undefined; use `hasConcreteAuth` to distinguish) → balance omitted (rest of line unaffected; README tells the user to add the DeepSeek provider key in OMP's provider settings — the one place it is entered, exactly once); HTTP 401 → `bal ✕`, retry after config `balanceRetrySec` (default 300); network error → keep the last value silently, retry next cycle. Refresh cadence is near-real-time: every config `balanceRefreshSec` (default 15) while the segment is visible, with an immediate refresh when the segment becomes visible; no refresh while hidden.
Tests: injected fetch + injected key resolver — success (USD-only row; CNY-only row; mixed rows), 401, network error, resolver-undefined (no auth configured → balance omitted, no crash); display-currency rule unit tests — CNY row present (incl. mixed) → zh-cn ¥ table + ¥ balance; USD-only → en $ table + $ balance; no balance data yet → CNY default; `displayCurrency: "USD"|"CNY"` override pins table + row; balance arriving later flips auto (USD-only) exactly once.

### Phase 6 — DeepSeek-in-use predicate + visibility (`lib/active.ts`)
`deepseekActive` = true iff any: (a) DeepSeek request activity (main or subagent ledger `lastTs`) within 60 s; (b) current/last main-session `ctx.model` is DeepSeek; (c) session tree has DeepSeek usage this session (keeps cost line visible through short Codex stretches after a fallback block). Line renders when (a)/(b) true and stays while (c); hides when none AND config `alwaysShow` is false (default). `alwaysShow: true` pins it visible. Requirement is "renders every time DeepSeek is in use" → active-driven visibility is the default.
Tests: transitions — pure-Codex session hidden; DeepSeek `message_end` → visible; deepseek subagent ledger touched while main Codex → visible; >60 s idle + no usage → hidden; `alwaysShow` → visible.

### Phase 7 — Status line registration (`extensions/index.ts`)

The 1 s interval updates ONLY the countdown digits; data refreshes are event- or cadence-driven: balance every `balanceRefreshSec` (15 s) while visible + immediately on visibility gain, pricing fetch-once / `--force-refresh` per Phase 3, cost on every usage event and subagent ledger change (fs.watch + 10 s fallback scan while a DeepSeek session is live).
- Status text — single key `"deepseek"`, PLAIN TEXT (setStatus strips ANSI; verified) — phase glyphs convey state:
  `◐ off-peak →peak 09:00 in 5h 12m | v4-flash ¥1.5m/¥0.05h/¥4.5o · v4-pro ¥4.5m/¥0.15h/¥13.5o | bal ¥110.00 | session ¥2.31` (CNY account; zh-cn table values, off-peak shown) — auto rule: mixed/CNY account shows ¥ values, USD-only account flips to en-table `$`; `displayCurrency` pins one currency; one balance row in the same currency.

- Countdown target: next weekday-schedule boundary (span start when off-peak, span end when in peak).
- deepakness.com/deepseek is UI inspiration only — no data from it.

### Phase 8 — In-app configuration (no `/settings` contribution exists — verified; this is the native equivalent)
- Persisted config file **`~/.omp/agent/ds-statusline.yml`** — YAML, user-requested location/format (path = `join(getAgentDir(), "ds-statusline.yml")`; `getAgentDir()` defaults to `~/.omp/agent`; sits next to OMP-core `config.yml`, which this extension never reads or writes), flat schema, keys + defaults: `enabled: true`, `alwaysShow: false`, `timezone: ""` (blank = system local), `displayCurrency: auto` (`auto|USD|CNY`; auto = CNY-first, Phase 5), `balanceRefreshSec: 15`, `balanceRetrySec: 300`. Config I/O is dependency-free flat YAML (`lib/config.ts`): the reader tolerates `#` comments, single/double-quoted strings, and bare `key: value` scalars; unknown keys are preserved verbatim (forward-compatible); missing or malformed file → defaults (log once on corrupt, never auto-overwrite). Re-read on every status tick and command invocation → a hand edit applies ≤ 1 s; `/ds-statusline` rewrites the file ON THE USER'S BEHALF (known keys in file order, unknown keys kept, comments dropped — documented in README). **No API-key field and no pricing TTL exist in the schema — the key comes from OMP's own provider configuration (Phase 5); pricing is fetched once per currency and kept forever until force refresh (Phase 3).**
- Slash command `pi.registerCommand("ds-statusline", …)`: handler first checks `args`; `--force-refresh` (or bare `/ds-statusline --force-refresh`) re-fetches + re-parses the official page and atomically overwrites `pricing-cache.json` (fetch failure → keep the existing cache, `notify` "refresh failed"; never delete the cache). Interactive (no flag): opens `ctx.ui.askDialog` (or `select`/`input` fallbacks when askDialog is unavailable in non-TUI modes) with options: show always (`alwaysShow` toggle), timezone override (text, blank = system local), cost display currency (auto / USD / CNY), balance refresh seconds, and a "refresh prices now" action (same as `--force-refresh`). Persists via atomic write (write temp + rename) and notifies `ctx.ui.notify("deepseek-statusline: saved")`; config changes re-render immediately, price refreshes re-render immediately after the fetch settles.
- README documents: install (`omp plugin install @ultra-omp/pi-deepseek-statusline`), `/ds-statusline` command, config fields + defaults incl. the `displayCurrency` auto rule (CNY-first; pin USD/CNY via command or YAML), the config file `~/.omp/agent/ds-statusline.yml` (hand-editable; `/ds-statusline` writes it for you), the no-key design (balance uses the DeepSeek provider key configured once in OMP's provider/settings screen), feature list, Implementation notes (Phase 1 findings).
Tests: config read/merge/defaults/corrupt-file/unknown-keys-preserved; hand-edited file content is picked up on the next tick; command handler with mocked `ctx.ui` (askDialog path + non-TUI fallback path) persists expected YAML (right keys + values; comments of a pre-existing file may drop); atomic-write leaves no temp file behind.

## Risks & edge cases
- Pricing page markup/URL churn → trailing-slash canonical; parser on real tables; cache kept forever until `/ds-statusline --force-refresh`; no offline constants — never fabricate prices.
- Weekly multi-window schedule + weekends + DST → epoch-instant recurrence; test vectors above.
- Mid-session fallback invisible to static model fields → per-request event attribution (Phase 6 a+b).
- Subagent cost/visibility latency → ledger files + fs.watch + 10 s scan.
- Usage-output key unknown until pi-ai types installed → A3b fallback chain; unpriced output if absent.
- No `/settings` contribution capability → in-app command config (Phase 8); documented in README.
- setStatus strips ANSI → plain text + glyphs (Phase 7); never rely on color.
- Key resolution: provider id or registry method naming differs in the installed runtime → A4c fallback (provider string from observed deepseek `ctx.model`; compile-time check against installed `ModelRegistry` types); if the runtime truly exposes no key accessor, balance is omitted with the "add DeepSeek provider key in OMP settings" hint — the rest of the line is unaffected. Never prompt for a key.
- Mixed USD+CNY accounts → auto shows CNY (DeepSeek-native, user-chosen default) for balance + prices + session cost; `displayCurrency: USD|CNY` pins the other any time (command or YAML). "Larger balance wins" was rejected: comparing CNY vs USD amounts requires an FX rate, and third-party FX is excluded — no cross-currency math anywhere (no FX, no summing, no conversion).
- No DeepSeek auth configured / 401 / offline → degrade per Phase 5; async fetches, cadence-gated, never block UI. Cost buckets are priced against the cached schedule at event time; a `--force-refresh` that changes prices/schedule reprices display from then on (past events keep their event-time phase buckets — documented behavior, user-triggered).

## Assumptions (user-overridable; defaults used if not answered)
- Peak/off-peak prices and the weekday schedule come exclusively from the two official locale pages (en = USD `…/quick_start/pricing/`, zh-cn = CNY `…/zh-cn/quick_start/pricing/`, both trailing-slash), fetched once per currency on first use and kept forever until `/ds-statusline --force-refresh`. Session cost is always priced from ONE official table in the displayed currency — `displayCurrency` auto resolves CNY-first when both balance currencies exist (native currency; a balance-magnitude comparison would need FX, which is excluded) and is overridable to USD or CNY — no FX conversion anywhere.
- Session cost = DeepSeek-attributed usage of the current main session plus subagent sessions in the same cwd started within 60 s of the main session start (or parent-session id when core exposes it — Phase 1 A3c).
- The DeepSeek balance key is the provider key already configured once in OMP (resolved via `ctx.modelRegistry`); the extension requires no key entry, env, or storage.
- Defaults: pricing fetched once per currency on first use and kept forever (refreshed only via `/ds-statusline --force-refresh`); balance refreshed near-real-time every 15 s while visible (immediate on visibility); session-cost estimates updated on every usage event (per turn and per tool call); 1 s tick drives only the countdown; hidden when no DeepSeek model is in use — all configurable in-app via `/ds-statusline`.
- User config file: `~/.omp/agent/ds-statusline.yml` (YAML, extension-owned; sits beside OMP-core `config.yml`, which core owns and this extension never touches; cache/ledgers stay under `extensions/deepseek-statusline/`). `displayCurrency: auto` is CNY-first; hand edits and `/ds-statusline` writes both apply.
